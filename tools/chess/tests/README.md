# 棋谱库的测试

着法树和 PGN 解析的 bug 很隐蔽（变招静默丢失、导出后结构变形、
保存时覆盖了别的棋局），肉眼看不出来，所以**改 `pgn.js` / `board.js` /
`app.js` 之前先把测试跑起来**。

## 怎么跑

```bash
# 1. 起本地服务（在 个人工作台/ 目录下）
python3 -m http.server 8799

# 2. 另开一个终端，在 个人工作台/ 目录下跑
node tools/chess/tests/pgn.test.js        # PGN 解析 + 导出，不需要服务
python3 tools/chess/tests/ui.test.py      # 界面交互，需要上面的服务
```

Node 那个没有依赖。Python 那个需要 playwright：
`pip install playwright && playwright install chromium`

## 各个文件测什么

| 文件 | 覆盖 |
|---|---|
| `pgn.test.js` | 解析主变 / 头部标签 / **变招挂载位置** / 嵌套变招 / 注释和 NAG / 王车易位 / 升变 / 自定义 FEN / **round-trip 结构一致** / 容错 / 性能 |
| `ui.test.py` | 棋盘渲染 / 点选走子 / **走不同的棋要开分支且主变不变** / 升变弹窗 / 保存和刷新 / **「再下一盘」不能动已存棋局** / 防丢棋确认 / 移动端布局 |

## 最关键的几条（别删）

1. **round-trip 结构指纹**：解析 → 导出 → 再解析，递归拼
   `san + 子树` 得到指纹，两棵树必须完全相同。这条最能抓出
   变招丢失和括号位置写错
2. **在已有着法上走不同的棋 → 必须新增分支，主变不变**。
   这是这个工具存在的理由
3. **「再下一盘」后已保存的棋局数量不能变**。用户明确担心过这点
4. **脏状态下切换/清空/导入都要弹确认，取消后棋还在**

## 性能门槛

真实名局 87 手：解析 + 导出 + 再解析 < 150ms。
20 局连续导入 < 1.5s。超了就是引擎或解析器退化了，手机上会卡。
